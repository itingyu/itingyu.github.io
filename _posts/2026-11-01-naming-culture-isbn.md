# 命名系统（7）：知识与文化——书的身份证与颜色的方言

最后一篇讲文化产品。这一类的麻烦在于：**对象本身没有清晰的边界**。一本书有精装平装、一个作品有不同版本、一种颜色在不同介质上根本不是同一个东西。

所以这里的命名系统，往往不是「一个对象一个号」，而是「一个对象一族号」。

## 图书：ISBN 的五段结构

ISBN 由[国际 ISBN 中心](https://www.isbn-international.org/)统一规划，各国机构再分配组区与出版者号。

```
978 - 7 - 111 - 12345 - 3
│     │   │      │      └─ 校验位
│     │   │      └──────── 书名号（出版者自编）
│     │   └─────────────── 出版者号（长度可变）
│     └─────────────────── 组区（7 = 中国大陆）
└───────────────────────── 商品前缀（978 图书、979 乐谱）
```

组区号的分配有历史：`0`、`1` 英语，`2` 法语，`3` 德语，`4` 日语，`5` 俄语，`7` 中文。组区号越短，出版量越大——这是按历史产量分配的稀缺资源。

出版者号的长度不固定，由各国 ISBN 机构分配：大出版社拿短号，小出版社拿长号。所以出版者号有 2 到 7 位不等，但 ISBN-13 的总位数始终是 13 位。

### 期刊与论文

- **[ISSN](https://www.issn.org/)**：8 位，期刊专用，`1234-5679`，最后一位可能是 `X`（代表 10）
- **DOI**：`10.1000/xyz123`，前缀 `10.` + 注册机构号 + 后缀，后缀由出版方自定，但要求全球唯一
- **ORCID**：16 位，研究者标识，解决同名同姓问题

### 分类法：三套书架逻辑

| 体系 | 结构 | 特点 |
|:--|:--|:--|
| 中图法 | 22 个基本大类 A-Z | 中国图书馆通用 |
| DDC 杜威十进 | 10 大类 000-900 | 英美公共图书馆 |
| LCC 国会法 | 21 个字母大类 | 研究型图书馆 |

同一个学科在三套里的位置完全不同。做文献检索时，分类号不能跨体系直接换算。

## 音乐：作品号不是创作顺序

古典音乐的作品号是最容易误解的一类编码。

| 编号 | 对象 | 编制者 |
|:--|:--|:--|
| Op. | 一般作品 | 出版商，按出版顺序而非创作顺序 |
| BWV | 巴赫 | Schmieder，1950 |
| K. / KV | 莫扎特 | Köchel，1862 |
| Hob. | 海顿 | Hoboken |
| D. | 舒伯特 | Deutsch |
| RV | 维瓦尔第 | Ryom |

**`Op.` 是出版号，不是创作号。** 同一部作品可能因为再版拿到不同的 Op. 号，也可能生前未出版、死后才编号。所以研究一部作品，必须指明用的是哪套目录。

现代录音则有另一套：

- **ISRC**：12 位，`国别 2 + 登记机构 3 + 年份 2 + 序号 5`，标识一段录音
- **ISWC**：标识词曲作品，不是录音
- 同一首歌的录音和作品是两个号，翻唱换 ISRC 不换 ISWC

## 影视：一个作品，多个版本

`ISAN`（国际标准音像号）是 24 位十六进制，分段表示根、集、版本。设计上就考虑了「一部剧有多集、一集有多个剪辑版本」。

`EIDR` 走 DOI 风格，`10.5240/XXXX-...`。`IMDb tt` 号虽然不是标准，但事实上成了引用默认值——论文、影评、数据库都在用。

影视命名的核心难题是版本：院线版、导演剪辑版、修复版、不同国家的分级版，算不算同一个对象？ISAN 的答案是「根作品一个号，版本另给号」，这也是大多数内容管理系统的做法。

## 色彩：没有唯一标准的领域

颜色是个例外——它有大量命名体系，但没有一个能覆盖全部场景。

| 体系 | 例子 | 领域 |
|:--|:--|:--|
| Pantone | 185 C | 印刷专色 |
| RAL | RAL 5015 | 涂料、工业 |
| NCS | S 2050-Y10R | 建筑、北欧 |
| Munsell | 5YR 6/8 | 色彩科学、土壤 |
| Hex / sRGB | #E4002B | 屏幕 |
| CIELAB | L\*a\*b\* | 色差计算 |

NCS 的结构最「语法化」：`S 2050-Y10R` = 标准色，黑度 20%，彩度 50%，色相为黄中偏红 10%。

**关键事实：这些体系之间只能近似转换，不能精确互转。** Pantone 185 C 在屏幕上没有唯一对应值，因为专色油墨和发光屏幕的呈色原理不同。

所以印刷厂说「这个红不对」时，第一个问题永远是：你说的是哪个体系的红？

## 食品与农业：安全与产地

### 添加剂

- **E 编号**（欧盟）：E100–E1520，E 开头加数字，按类别分段（E100-199 色素、E200-299 防腐剂、E300-399 抗氧化剂）
- **INS 号**（国际食品法典）：与 E 编号大体对应，但编号规则不同
- 中国用 GB 2760 的品种名单，不强制标 E 号

同一个物质三个身份：柠檬黄 = E102 = INS 102 = 酒石黄。

### 农产品

- **品种审定编号**：作物名 + 年份 + 序号，如「国审稻 20200001」，由审定委员会发号
- **UPOV 品种权**：品种名全球唯一，且不得与已有品种混淆，命名规则由国际植物新品种保护联盟统一
- **地理标志**：欧盟分 PDO（原产地保护）、PGI（地理标志保护）；法国有 AOC，意大利有 DOCG，美国有 AVA

地理标志的本质是**用地理边界定义命名权**：只有香槟区产的起泡酒能叫 Champagne，这是法律问题，不是技术问题。

### 零售

散装果蔬用 **PLU 码**：4 位常规码，5 位以 `9` 开头表示有机。收银员敲的那四个数字，就是一套全球通行的农产品命名。

## 软件：给虚拟对象发号

软件行业的命名是自发生长的，反而最有借鉴意义。

| 体系 | 形态 | 解决的问题 |
|:--|:--|:--|
| SemVer | `1.4.2` | 声明兼容性：主版本不兼容、次版本加功能、修订版修 bug |
| CalVer | `2024.10` | 按时间发布，适合持续交付 |
| UUID v4 | `550e8400-...` | 无中心发号，随机保证唯一 |
| UUID v7 | 时间有序 | 解决 v4 做数据库主键时索引碎片化 |
| 反向域名 | `com.example.app` | 借用域名所有权保证包名全球唯一 |

SemVer 的精妙之处是把「兼容性」这件主观的事，变成了三个数字的机械约定。代价是：一旦有人不守规矩，整个生态的信任就崩了——这也是为什么很多项目干脆锁死版本。

## 七篇之后

回头看，六种机制在各行业反复出现，只是组合方式不同：

| 机制 | 典型 |
|:--|:--|
| 语法生成 | IUPAC、SI、NCS |
| 层级编码 | HS、ICD、中图法、行政区划 |
| 登记流水 | CAS、ISBN、ISAN、LEI |
| 助记约定 | IATA、基因符号、Pantone |
| 型号规格 | 轴承、钢材、封装、VIN |
| 版本演进 | SemVer、ISAN 版本段 |

三条通用规律，值得在设计任何编码体系时默念：

1. **名字必须锚在实物上**。模式标本、金钉子、标准物质、IMO 号——没有锚点，名字会随解释漂移。
2. **语义和稳定只能二选一，所以通常要双轨**。给人看的名字 + 给机器用的号。
3. **校验位是廉价的保险**。一位容量，换掉大部分人工录入错误，只要有人工环节就该加。

最后一个判断标准，来自一位做标准化工作的前辈：**好的命名系统，是五十年后的人还能查得到、对得上、不改也能用的那一套。**

以此收尾。
